## Overview

Build everything a token needs *before* any endpoint exists: the two settings blocks, the
`RefreshToken` table, a pure encode/decode service, an ORM selector, the DRF authentication
class, and a rewrite of `apis/selectors/auth_tokens.py` so the password endpoints stop
importing `oauth2_provider`.

## Key insights

- **`authenticate_header()` is not optional.** DRF's `APIView.handle_exception` downgrades
  `NotAuthenticated`/`AuthenticationFailed` to **403** when
  `get_authenticate_header()` is falsy. `giapha/tests/test_permissions.py::test_anonymous_gets_401_not_404`
  and `apis/tests/test_profile_api.py::test_unauthenticated_is_401` both fail without it.
- **Return `None`, do not raise, when the header is absent or is not `Bearer`.** Raising
  turns every anonymous request to a public endpoint (`/api/home`, `/api/calendar`) into a 401.
- **`pwd` claim replaces server-side access-token revocation.** `sha256(user.password)[:16]`
  changes the moment `set_password()` runs, so every issued access token dies with the
  password change — no DB row, no revocation table. This is what lets `revoke_all_tokens`
  shrink to "delete the refresh rows".
- **No `revoked_at` column.** Rotation and logout DELETE the row. `docs/system-architecture.md`
  L184-189 records why DOT's *soft* revoke was a trap here; do not reintroduce the shape.
- `USE_TZ=True` and `TIME_ZONE='UTC'` → always `django.utils.timezone.now()` /
  `datetime.now(tz=timezone.utc)`. PyJWT silently mis-handles naive datetimes.
- PyJWT 2.x `jwt.encode()` returns `str` (not bytes) and `jwt.decode()` **requires**
  `algorithms=[...]`.
- `apis/services/jwt_tokens.py` must stay pure (no ORM, no `request`) so it is testable on
  `SimpleTestCase` — reading `settings` is allowed, `apis/services/otp.py` already does it.

## Requirements

**Functional**
- `encode_access_token(user)` → a HS256 JWT carrying `sub`, `exp`, `iat`, `jti`, `pwd`.
- `decode_access_token(token)` → claims dict, or raises `jwt.InvalidTokenError` subclass.
- A refresh token is a `secrets.token_urlsafe(32)` string; only its sha256 hex is stored.
- `Authorization: Bearer <jwt>` authenticates; expired / tampered / wrong-`pwd` / inactive
  user → 401. Absent or non-Bearer header → anonymous (not an error).
- `set_password_and_revoke_tokens(user, pwd)` keeps its existing signature and callers.

**Non-functional**
- Every new file < 200 lines. No new package in `requirements.txt`.
- Authentication costs exactly **1 query** (the `User` fetch).
- `manage.py makemigrations apis --check --dry-run` clean after 0074.

## Architecture

```
Authorization: Bearer <jwt>
  -> apis.authentication.JWTAuthentication.authenticate()
       services.jwt_tokens.decode_access_token()      (pure, no ORM)
       User.objects.get(pk=claims['sub'])             (1 query)
       compare_digest(claims['pwd'], fingerprint)     -> 401 on mismatch
       user.is_active                                 -> 401 on inactive
     -> (user, claims)

password change/reset
  -> selectors.auth_tokens.set_password_and_revoke_tokens()
       user.set_password(); user.save(update_fields=['password'])   # kills access tokens
       RefreshToken.objects.filter(user=user).delete()              # kills refresh tokens
     both inside one transaction.atomic()
```

6. **Service** `apis/services/jwt_tokens.py` — pure. Shape:

```python
ALGORITHM = 'HS256'

def password_fingerprint(password_hash):
    """First 16 hex chars of sha256(user.password). Changes on every set_password()."""
    return sha256((password_hash or '').encode('utf-8')).hexdigest()[:16]

def encode_access_token(user_id, password_hash, now=None):
    """Returns (token, expires_in_seconds). `now` is injectable so tests can mint
    an already-expired token without sleeping."""
    now = now or datetime.now(tz=timezone.utc)
    lifetime = settings.JWT_ACCESS_TOKEN_LIFETIME_SECONDS
    claims = {'sub': user_id, 'iat': now, 'exp': now + timedelta(seconds=lifetime),
              'jti': uuid4().hex, 'pwd': password_fingerprint(password_hash)}
    return jwt.encode(claims, settings.JWT_SIGNING_KEY, algorithm=ALGORITHM), lifetime

def decode_access_token(token):
    """Raises a `jwt.InvalidTokenError` subclass. Callers translate to 401."""
    return jwt.decode(token, settings.JWT_SIGNING_KEY, algorithms=[ALGORITHM])

def generate_refresh_token():
    return secrets.token_urlsafe(32)          # ~256 bits

def hash_refresh_token(raw):
    return sha256(raw.encode('utf-8')).hexdigest()   # 64 chars == token_hash max_length
```
   `sub` is an int here; PyJWT does not enforce RFC 7519's "sub must be a string" in 2.6.0.
   Keep it int and say so in the docstring, so nobody "fixes" it and breaks live tokens.
   Plain `sha256` (not HMAC) is right for the refresh token: unlike the 6-digit OTP its
   256-bit entropy is the security, so a keyed digest buys nothing — say this in the
   docstring, because `apis/services/otp.py` argues the opposite case for the OTP.

7. **Selector** `apis/selectors/refresh_tokens.py` — the only ORM in the token path:

```python
def issue_token_pair(user):
    """Mint an access token + a NEW refresh row. Returns the response payload dict.
    The raw refresh token is returned once and never stored."""
    raw = generate_refresh_token()
    RefreshToken.objects.create(
        user=user, token_hash=hash_refresh_token(raw),
        expires_at=timezone.now() + timedelta(seconds=settings.JWT_REFRESH_TOKEN_LIFETIME_SECONDS))
    access, expires_in = encode_access_token(user.pk, user.password)
    return {'access_token': access, 'refresh_token': raw,
            'token_type': 'Bearer', 'expires_in': expires_in}

def consume_refresh_token(raw):
    """Delete the row `raw` names and return its user, or None.

    The DELETE's rowcount is the race check: two concurrent refreshes both read
    the row, only one deletes it, and the loser gets None -> 401. A read-then-
    issue without this would hand out two live sessions for one token.
    """
    row = RefreshToken.objects.filter(
        token_hash=hash_refresh_token(raw), expires_at__gt=timezone.now()
    ).select_related('user').first()
    if row is None:
        return None
    deleted, _ = RefreshToken.objects.filter(pk=row.pk).delete()
    return row.user if deleted else None

def delete_refresh_token(raw):
    """Logout. Returns the number of rows removed (0 is not an error)."""
    return RefreshToken.objects.filter(token_hash=hash_refresh_token(raw)).delete()[0]
```

8. **Authentication class** `apis/authentication.py` (top level, alongside
   `apis/exceptions.py` — it is DRF plumbing, not a view/selector/service):

```python
class JWTAuthentication(BaseAuthentication):
    keyword = 'Bearer'

    def authenticate(self, request):
        header = get_authorization_header(request).split()
        if not header or header[0].lower() != b'bearer':
            return None            # anonymous, NOT an error: public endpoints must still work
        if len(header) != 2:
            raise AuthenticationFailed(INVALID_HEADER)
        try:
            claims = decode_access_token(header[1].decode('utf-8'))
        except (jwt.InvalidTokenError, UnicodeDecodeError):
            raise AuthenticationFailed(INVALID_TOKEN)     # one message for every failure mode
        try:
            user = User.objects.get(pk=claims.get('sub'))
        except (User.DoesNotExist, ValueError, TypeError):
            raise AuthenticationFailed(INVALID_TOKEN)
        if not user.is_active:
            raise AuthenticationFailed(INVALID_TOKEN)
        if not compare_digest(claims.get('pwd', ''), password_fingerprint(user.password)):
            raise AuthenticationFailed(INVALID_TOKEN)     # password changed since issue
        return (user, claims)

    def authenticate_header(self, request):
        # Load-bearing: without it DRF answers 403, not 401, for anonymous callers.
        return 'Bearer realm="api"'
```
   All failures share one message — an attacker must not learn whether the id existed.

def revoke_all_tokens(user):
    """Delete every refresh token of `user`. Returns the count.

    ACCESS tokens are not stored and cannot be deleted: they are killed by the
    `pwd` claim (services/jwt_tokens.password_fingerprint), which stops matching

## Deviations from plan

1. **RefreshToken model gained `password_fingerprint` field** (CharField(16)): Migration 0074 stores and checks this value on token consumption, ensuring that any password change (including via admin/shell/changepassword) immediately invalidates all refresh tokens. Closes the code-review HIGH finding (H1).
2. **`sub` claim is now a STRING** (RFC 7519 compliant), not int: User ID stored and validated as `str(user_id)`, which aligns with the JWT standard and simplifies future upgrades to PyJWT >= 2.10.
3. **Refresh operation wrapped in `transaction.atomic()`**: consume + issue pair now atomic, eliminating any risk of two live tokens if a failure occurs between DELETE and INSERT.
4. **`sensitive_variables` decorator added to selector functions**: `password_fingerprint`, `encode_access_token`, `consume_refresh_token` all decorated to mask sensitive data in error reports.

## Security considerations

- The refresh token is a **credential**: stored hashed, returned exactly once, never logged,
  never echoed back on any other endpoint (`docs/code-standards.md` → "A credential is
  write-only").
- Signing key: dedicated env var, falls back to `SECRET_KEY`. Rotating it invalidates every
  access token *and* leaves the refresh rows valid — a refresh call re-mints under the new
  key, so rotation is not a mass logout unless the rows are cleared too. Say this in phase 05.
- Access tokens are unrevokable within their 1-hour lifetime except via password change.
  That is the accepted trade for statelessness; keep the lifetime short.
- One generic `AuthenticationFailed` message for every failure mode — no oracle for
  "user id exists", "token expired" vs "signature bad".
